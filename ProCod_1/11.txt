### 🔍 What is **Specificity** in CSS?

**Specificity** is the set of rules browsers use to determine **which CSS rule wins** when multiple rules target the same element.

Think of it like a **priority system**—the more *specific* a selector is, the more weight it carries.

---

### 🧠 The Specificity Hierarchy

Specificity is calculated using a 4-part scoring system: **`a,b,c,d`**

| Selector Type         | Specificity |
|----------------------|-------------|
| Inline styles         | `a=1`       |
| IDs (`#id`)           | `b=1`       |
| Classes, attributes (`.class`, `[type=button]`), pseudo-classes (`:hover`) | `c=1` |
| Elements (`div`, `h1`) and pseudo-elements (`::before`) | `d=1` |

> The higher the number on the left, the stronger the rule.

---

### 🧮 Examples

```css
/* 1. Element selector: 0,0,0,1 */
div {
  color: blue;
}

/* 2. Class selector: 0,0,1,0 */
.container {
  color: green;
}

/* 3. ID selector: 0,1,0,0 */
#main {
  color: red;
}

/* 4. Inline style: 1,0,0,0 */
<div style="color: purple;">Hello</div>
```

👉 The order of power is:

`Inline styles > IDs > Classes > Elements`

---

### 🔁 When Specificity Conflicts

If two rules apply to the same element, the one with **higher specificity** wins.

```html
<div id="box" class="container">Hello</div>
```

```css
#box { color: red; }         /* 0,1,0,0 */
.container { color: green; } /* 0,0,1,0 */
```

➡️ `#box` wins because its specificity is higher.

---

### ❗️Important Notes

- If two selectors have **equal specificity**, the **last one declared** wins (source order).
- You can override specificity with `!important`, but it should be avoided unless necessary.

---

### 🧠 Tip: Think of it like a score!

| Selector                | Specificity Value |
|-------------------------|-------------------|
| `div`                   | 0,0,0,1           |
| `.box`                  | 0,0,1,0           |
| `#main`                 | 0,1,0,0           |
| `div.box#main`          | 0,1,1,1           |
| `style="..."` (inline)  | 1,0,0,0           |
